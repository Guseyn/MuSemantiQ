Training on a server

Clone the project on a rented server, train there, keep the model out of git, and bring the weights home to test. Every command on this page is typed on your laptop — the server is only ever reached over ssh.

the shape set up once a training run model data bring it home test locally cheat sheet

1The shape of it ↑

Three facts make this simple:

  • Training needs nothing but Node — no npm install on the server. The trainer and the data factory are dependency-free.
  • The dataset does not exist as files — it is drawn from seeds. The same seed on both machines gives the same bytes, so nothing to sync.
  • Weights are data, not source — they are gitignored and travel directly to you.

2Set up the server, once ↑

Any CPU droplet with 4–8 vCPU will do; the model is small and the trainer uses the CPU. From your laptop:

ssh-copy-id user@server        # so every ssh below needs no password
git push -u origin omr         # the branch goes to GitHub first

ssh user@server 'git clone https://github.com/Guseyn/MuSemantiQ.git && cd MuSemantiQ && git checkout omr && node -v'

node -v should print v22 or newer — that is the server's only requirement. To type less, add a host alias to ~/.ssh/config and use it in place of user@server everywhere below:

Host omr
  HostName server
  User user

3A training run ↑

ssh user@server 'cd MuSemantiQ && git pull'                        # the latest code

ssh user@server 'cd MuSemantiQ && nohup node src/omr/training/train.js --out=src/omr/model/weights.json > /dev/null 2>&1 & echo "training: pid $!"'

The second command returns immediately and the training keeps running after ssh hangs up — nohup detaches it. The run logs itself to training-data/training.log on the server: the config it started with, one line per epoch, the sha of the weights it wrote, and any error it died of. Watching is another one-liner; Ctrl-c stops the watching, not the training:

ssh user@server 'tail -f MuSemantiQ/training-data/training.log'   # one line per epoch

ssh user@server 'pkill -f train.js'                               # to stop the run
Reproducible The seeds live in the run itself: the same code and seed give the same dataset and the same weights on any machine. The seed and shape are in runTraining() in src/omr/training/train.js.

4Model data stays out of git ↑

Already in .gitignore, on both machines alike:

# The trained model and its runs: generated on the training server and copied
# home by hand. The dataset is not here at all — seeds regenerate it.
# Weights are data, not source.
src/omr/model/weights.json
src/omr/model/checkpoints/
training-data/

So git status on the server stays clean while a run lives in model/, and a weights file can never be committed by accident.

5Bring the model home ↑

rsync -av user@server:~/MuSemantiQ/src/omr/model/ ./src/omr/model/
rsync -av user@server:~/MuSemantiQ/training-data/training.log ./training-data/   # optional: the run history

shasum -a 256 src/omr/model/weights.json                   # must match the sha in the log

The trainer hashes exactly the bytes it wrote, so a mismatch means a broken transfer or a different run — re-rsync before trusting the file. Once the weights are in src/omr/model/, the code picks them up where you load them (see below).

6Test it locally ↑

The API under test

The one that matters is the first line: any image → MSQ. The others are the same pipeline taken apart.

functionin → out
translateImageToMsq(image, { model, classIds })an image → { msqText, report } — the main test
translateImagesToMsqPages(images, options)one image per page → { pagesText, report }, with key and meter carried across
decodeImageToGrayscale(bytes)png bytes → { width, height, grayscale }
analyzeImage(image)the image → staves, systems, symbols, measured styles
readBitmapFromImage(pixels)canvas ImageData → the same numbers (the browser path)

The main test — any image becomes MSQ

# node --input-type=module -e "…paste this…"
import { readFileSync, writeFileSync } from 'node:fs'
import { decodeImageToGrayscale, translateImageToMsq } from '#msq/omr/api.js'
import { modelFromWeights } from '#msq/omr/training/exportWeights.js'

const { shape, layers, classIds } = JSON.parse(readFileSync('src/omr/model/weights.json', 'utf8'))
const model = modelFromWeights({ shape, layers })

const image = decodeImageToGrayscale(readFileSync('score.png'))
const { msqText, report } = translateImageToMsq(image, { model, classIds })

writeFileSync('score.msq', msqText)
console.log(report.uncertain)     // what the tool was unsure of, with its MSQ line

Then read score.msq — it is plain MSQ text; open it in Unison or run it through the parser. A JPEG is not decoded: convert it first with sips -s format png photo.jpg (macOS) or magick photo.jpg photo.png, or in a browser hand the canvas pixels to readBitmapFromImage.

And everything around it

npm run test:omr:all

The suite covers the parts: the PNG round trip, rules and math against drawn pages, and the golden byte-stable outputs. The weights file carries its own classIds, so the order the model was trained with is never reconstructed from memory. A quick check that the transferred model itself speaks:

# node --input-type=module -e "…paste this…"
import { readFileSync } from 'node:fs'
import { modelFromWeights } from '#msq/omr/training/exportWeights.js'
import classifyComponent from '#msq/omr/analysis/classifyComponent.js'
import { generateTrainingSet } from '#msq/omr/training/generateTrainingSet.js'

const { shape, layers, classIds } = JSON.parse(readFileSync('src/omr/model/weights.json', 'utf8'))
const model = modelFromWeights({ shape, layers })
const { samples } = generateTrainingSet({ seed: 1, samplesPerClass: 1, gridSize: shape.gridSize })
for (const sample of samples) {
  const answer = classifyComponent(model, sample.pixels, classIds)
  console.log(sample.classId, '→', answer.className, answer.confidence)
}

7Cheat sheet ↑

Everything below, typed on your laptop:

# once
ssh-copy-id user@server
git push -u origin omr
ssh user@server 'git clone https://github.com/Guseyn/MuSemantiQ.git && cd MuSemantiQ && git checkout omr && node -v'

# every run
ssh user@server 'cd MuSemantiQ && git pull'
ssh user@server 'cd MuSemantiQ && nohup node src/omr/training/train.js --out=src/omr/model/weights.json > /dev/null 2>&1 & echo "training: pid $!"'
ssh user@server 'tail -f MuSemantiQ/training-data/training.log'   # Ctrl-c stops the watching, not the training

# take the result
rsync -av user@server:~/MuSemantiQ/src/omr/model/ ./src/omr/model/
rsync -av user@server:~/MuSemantiQ/training-data/training.log ./training-data/
shasum -a 256 src/omr/model/weights.json
npm run test:omr:all

Release weights come from one machine — different CPUs can round floats in the last decimal — and the printed hash is what pins the result. Once a weights.json is adopted, it never moves silently.
