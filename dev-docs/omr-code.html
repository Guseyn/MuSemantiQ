    The frozen pre-training sequence
    
    
    The order matters. Training starts only after the implementation and documentation are frozen and published. Full-page symbols and six-language OCR have separate manual entry points; the combiner creates the nested artifact that translation expects.
    
    
      
      
    1. Freeze and publish the reviewed code and docs. Use ./remote-training-scripts/prepare to run the permitted checks, generate the frozen bundle and upload the checkout.
      2. 
      
    2. On the remote trainer, generate and retain the frozen full-page bundle. Pin its code version explicitly; the default working-tree label is not a revision identifier:
      3. 
    
    
    
    node scripts/omr-prepare-remote.js --out=training-data/remote-bundle --code-version=<frozen-revision>
    
    
      
      
    1. Start full-page symbol training manually on the remote trainer, pointing at that frozen manifest:
      2. 
    
    
    
    node scripts/omr-train-full-page.js --data=training-data/remote-bundle/manifest.json --out=training-data/full-page-runs/<run-id>
    
    
      
      
    1. Run six-language OCR training manually on the remote trainer. scripts/omr-train-text.js is not a test entry point:
      2. 
    
    
    
    node scripts/omr-train-text.js --out=training-data/text-runs/<run-id> --seed=20261115 --grid=48 --epochs=20 --samples-per-character=4
    
    
      
      
    1. Choose the resulting full-page symbol and OCR artifacts, validate both through the combiner, and write one candidate with the OCR model nested under ocr:
      2. 
    
    
    
    node scripts/omr-combine-artifacts.js --symbols=<symbol-best-weights.json> --ocr=<ocr-best-weights.json> --out=<combined-candidate.json>
    
    
      
      
    1. Retrieve the chosen run outputs and compare their SHA-256 hashes. Then evaluate locally before adoption. Data generation and training outputs are not accuracy evidence by themselves.
      2. 
    
    
    
    node scripts/omr-evaluate-model.js --weights=<combined-candidate.json> --fixture=omr-cli-app/score.png
node omr-cli-app/omr.js --weights=<combined-candidate.json> --input=score.png --output=score.msq --diagnostics
    
    
    The older isolated renderer/template workflow is still present as train → runTraining(). It is separate from omr-prepare-remote.js → omr-train-full-page.js; the commands are not interchangeable.
    
    
    Regenerate this page after source changes with node scripts/build-omr-code-docs.js. The generator reads source files and writes only dev-docs/omr-code.html.
