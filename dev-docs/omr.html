src/omr — an image becomes a page

Everything implemented by hand: what each file does, the full math with every variable named, every MSQ feature it recognizes, and how training runs on a rented server. One small model; everything else is measuring pixels.

1Overview

Score image in → MSQ text + a report out. The report says what the tool was unsure about, with the place in the image and the line in the text. Draft, not copy.

The plan in one line each

  • Lines are geometry, blobs are classes. Staff lines, stems, beams and barlines are straight lines — found by math, not by the model. Only ink blobs (heads, clefs, accidentals, rests, digits) go through the classifier.
  • Proportions, not absolutes. Everything is measured in staff spaces; one screenshot at any zoom gives the same output.
  • The model is small — ~300K numbers you can print. Trained on pages your own renderer draws, so labels are exact and cost nothing.
  • Training is plain code: a forward pass, a loss, gradients, a nudging loop. Nothing hidden; the deployed model runs the same functions the trainer does.

3Every MSQ feature, and the pixels that prove it

Recognition is not magic: each MSQ feature corresponds to something visible and measurable in the image. If a feature has no visible signal in a given image, it goes to the report instead of being invented. Watch one measure go through the pipeline:

Grand staves and cross-stave writing

Multiple staves are not special cases. The page schema is built for them: a measure holds several staves, braces and brackets are connections between staves, and each note carries the stave it sits on (stave: 'prev' | 'current' | 'next'). The image gives the same signals as always — just across two grids:

  • Systems. A brace (curly) or bracket (thick line with serifs) at the left edge joins staves into one system; a barline drawn across staves confirms it. Measures then slice on the union of barline x-positions — a barline in either stave closes the measure for both.
  • Cross-stave chords and beams. A stem crossing the gap between staves joins heads from both — one unit, notes tagged stave: 'prev' | 'next' (the language words: on the next stave, on the previous stave). Beamed groups may cross the same way.
  • Cross-stave slurs and ties. Curve ends are paired as always; when the ends land on different staves, each is named by its (measure, stave, voice, unit) — the schema's span keys pair across staves. with s shape when it curves both ways; goes through unit for passing points.
  • A head between staves (ledger lines of both grids) belongs to the grid needing fewer ledger lines; stems and ties settle the rest. Still ambiguous → the report, with both candidates.

Every feature MSQ can write

The complete vocabulary of the language — every command in command-index.md, grouped as the language docs group it (578 constructs in docs/concepts.js). Each row: what proves it in the image, who reads it, when. The table is kept in step with the language: a new command forces a new row. 4Pixels → numbers

Before any recognition, the image becomes a coordinate system. This is plain measuring.

4.1 Staff space is the unit

s = mean(y2−y1, y3−y2, y4−y3, y5−y4)      û = (u − u0) / s deskewBitmap.js, detectStaves.js
y1..5row coordinates of the five staff lines, top to bottom, in pixels
sstaff space, in pixels — the one anchor; it never becomes music meaning
uany coordinate in pixels (x or y)
u0the origin (the staff's top-left corner)
ûthe coordinate in staff spaces — scale-free; two zooms of one page give the same û

4.2 Cutting out one symbol

Take a box of fixed musical size (3 s tall), pad it to a square — never stretch, aspect ratio carries meaning (stem vs notehead) — then scale it to 48×48. This is size normalization; the scaling inside is image resampling:

shrink:   dst(x, y) = (1 / |R|) · Σ(u,v) ∈ R src(u, v)   (average the pixels covered)
enlarge: dst(x, y) = (1−α)(1−β)·Q00 + α(1−β)·Q01 + (1−α)β·Q10 + αβ·Q11   (blend 2×2 neighbors) cropComponents.js
dst(x, y)the output pixel at column x, row y of the 48×48 crop
src(u, v)the source pixel at column u, row v of the original image
Rthe set of source pixels one output pixel covers (used when shrinking)
Q00..11the four source pixels around the sample point (used when enlarging)
α, βhow far the sample point sits between those four pixels, 0…1 each

Shrink by averaging, enlarge by blending — the other way round makes speckle. The same crop then always arrives as the same 48×48 numbers, whichever camera or zoom produced it.

4.3 Lines and blobs come apart

Straight lines (staff lines, stems, beams, barlines) are found by geometry — a line is a run of ink with a consistent angle, free to detect exactly. They are removed; what remains are components: connected blobs of ink. Those are what the model classifies. Lines never need learning.

4.4 The pixels go; the coordinates stay

Staff lines are measured before being subtracted, and their positions are kept. A note's position is measured against those stored coordinates — not against visible pixels. Each line is kept as a line model (a photo's stave is rarely perfectly flat):

yi(x) = ai·x + bi   (i = 1..5)      d = (yh − y3(xh)) / (s/2)      position = round(d) analysis/detectStaves.js → translation/assignPitchByStaffPosition.js
yi(x)row of staff line i at column x — stored from the measurement, survives subtraction
ai, bithe line's slope and offset (slope ≈ 0 after deskew; kept so tilted photos work)
xh, yhthe notehead blob's center
y3the middle line — the zero of the scale
s/2half a staff space: positions step by halves (line, space, line…)
d, position0 = middle line, odd = spaces, even = lines; then clefTable[clef][position] gives letter and octave

Subtraction cannot move the head's center — the lines pass through it horizontally and symmetrically — and when in doubt, the center is taken from the original grayscale using the blob's pixel mask.

  • Ledger lines extend the same grid. A short segment is a line again; it sits exactly one s from its neighbor, so position = nearest measured line ± 2 per staff space.
  • Damaged lines are reconstructed. Lines are equally spaced by definition, so a missing one is interpolated: ymissing ≈ yk ± (i−k)·s. The coordinate system survives even where pixels don't.

5The model, built by hand

A crop of 48×48 numbers goes in; K probabilities come out (K ≈ 50 classes — the whole vocabulary: heads, flags, dots, 9 accidentals, 8 clefs, rests, digits, 11 articulations, ornaments, ghost and grace heads, segno, coda, pedal…, and unknown. symbolClasses.js is data; K is whatever the vocabulary needs). The model is a chain of simple layers; each transforms an array of numbers.

5.1 What a convolution layer does

A convolution slides small pattern detectors (filters) over the image. Each filter produces one feature map — a grid saying "how much this pattern is present here". Implement it as one matrix multiply: cut every 3×3 window into a row of a big matrix (im2col), multiply once.

zi,j,k = bk + Σp=0..2 Σq=0..2 Σc Wp,q,c,k · ai+p, j+q, c model/forwardConvolution.js
i, jwhere the filter sits: output column and row
kwhich filter (of the 16 or 32); its index in the layer
p, qposition inside the 3×3 window of the filter (0, 1 or 2)
cinput channel (1 for the input image; 16 or 32 deeper in)
Wthe filter's numbers — learned; each filter is 3×3×channels of them
bbias: one learned number per filter, added after the sum
ainput values (the raw pixels, or the previous layer's output)
zoutput before activation

5.2 The other layers

ReLU:  a = max(0, z)      maxpool: apooli,j,c = max of a over the 2×2 window at (2i, 2j)      dense: z = W·a + b model/forwardDense.js
ReLU"turn negative to zero" — the cheapest way to let layers combine into any shape
maxpoolhalves the grid, keeps the strongest response — the image shrinks, the patterns survive
denseevery output connected to every input; after flatten it mixes everything into class scores
softmax:  pc = ezc − m / Σj ezj − m     where   m = maxj zj model/forwardDense.js
zcthe raw score for class c (higher = more likely)
pcprobability of class c; all p add up to 1
mthe biggest score, subtracted only so the exponentials don't overflow — same result
e≈ 2.718; ex is its exponential function
decision: class = argmaxc pc   if max p ≥ τ  ;  unknown otherwise analysis/classifyComponent.js
argmax"the class with the highest probability"
τthe confidence floor, e.g. 0.8 — below it the honest answer is unknown (goes to the report)

6Training, built by hand

Training means: show the model a crop with the known right answer, measure how wrong its guess was, and nudge every learned number to make the answer a little less wrong. Repeat ~106 times. Below is the entire idea in five steps.

6.1 The data: drawn by your own renderer

You never label anything. The generator writes random MSQ pages, your own drawer renders them, and since the drawer knows exactly what it drew, every symbol's class and position comes attached.

6.2 The loss: one number for "how wrong"

For a crop with known answer y, the model gives probability py to the right class. Perfect = 1 → loss 0. Confident and wrong → huge loss.

L = − (1/N) Σn=1..N log pn, yn + λ Σ θ2 training/train.js
Lthe loss: one number for the whole batch; training pushes it down
Nbatch size — how many crops are averaged at once (32)
nindex of the crop inside the batch
ynthe known right class of crop n (from the data factory)
pn,ynprobability the model gave to that right class
lognatural logarithm; −log(0.9) ≈ 0.10, −log(0.01) ≈ 4.6 — wrong-and-certain is punished hard
θall learned numbers together (weights W and biases b)
λtiny, e.g. 0.0005 — keeps the learned numbers small so the model can't memorize the training set

6.3 Gradients: who is to blame

A gradient answers one question per learned number: "if I nudge you up by a hair, does L go up or down, and by how much?" Chain rule, layer by layer, backward:

δfinal = p − onehot(y)      δz = δa ⊙ 1[z > 0] training/backpropagateDense.js
δ"delta": the error signal flowing backward, layer to layer
onehot(y)all zeros except 1 at the right class — so p − onehot is "how far the guess is from certain"
⊙multiply element by element
1[z > 0]1 where the value was positive, else 0 — ReLU only forwards blame where it passed signal
dW = δ · aprevT     db = Σ δ     δprev = WT δ training/backpropagateDense.js (+ convolution.js via im2col)
dW, dbgradients for the weights and biases — the blame for each learned number
aprevTthe previous layer's values, transposed (rows ↔ columns)
δprevthe blame handed further back; WT routes it through the connections

6.4 The nudge: Adam

gt = the gradient at step t
mt = β1 mt−1 + (1−β1) gt     vt = β2 vt−1 + (1−β2) gt2
θt = θt−1 − η · m̂t / (√v̂t + ε) training/updateWeightsWithAdam.js
gtthe gradient at training step t
mtsmoothed direction ("which way has the gradient pointed lately")
vtsmoothed size ("how big have the gradients been lately")
β1, β20.9 and 0.999 — how much history to keep
m̂, v̂m and v corrected for the first steps (when they start at 0)
ηlearning rate: nudge size, e.g. 0.001
ε10−8 — stops division by zero

7Training on a rented server

The trainer is plain Node — no framework, no GPU needed. A small server with 8–16 cores just makes it faster and keeps gigabytes of crops off your laptop. The workflow:

# 1 · put the code (and nothing else) on the server
rsync -a src/omr/ server:omr/

# 2 · generate the dataset there — seeded, so it exists everywhere by name
ssh server 'cd omr && node training/generateTrainingSet.js --seed 20261110'

# 3 · train; it writes loss.svg / confusion.svg each epoch
ssh server 'cd omr && node training/train.js'

# 4 · watch the pictures without downloading anything
rsync server:omr/run/*.svg ./run/        # open loss.svg after each epoch

# 5 · take the result home — weights + hash go into the repo
rsync server:omr/model/weights.json src/omr/model/
  • Same seed → same dataset on the server and on your laptop; only the speed differs.
  • Release weights come from one machine — different CPUs can round floats differently in the last decimal. The hash in the repo settles it anyway: once exported, weights never move.
  • A bigger server later is the same five commands; the model at ~300K numbers trains in an evening on 8 cores.

When a real image fails, reproduce it synthetically (new seed + harsher degradation) and keep it as a test. Real failure → synthetic reproduction → fixed → green. Nobody labels big images.

Terms, plainly

seed
one number that makes "random" repeatable. Same seed → the same pages, crops and shuffles, on any machine. Example: seed 42 always generates the same training page.
parameter
one learned number inside the model (a weight or a bias). The model ≈ 300K of them. Training is finding good values for them.
weights W
the filter numbers of the model. Multiply inputs by them; change them to change what the model detects.
bias b
one added number per filter/neuron; shifts how easily it fires.
convolution
sliding a small pattern detector (3×3 pixels) across the image, computing a weighted sum at every position.
feature map
the grid one filter produces: "how strongly the pattern appears" at each position.
activation a
the values a layer outputs — the input of the next layer. a = max(0, z) after ReLU.
softmax
turning raw scores into probabilities that add up to 1.
batch
a small group of crops (32) processed and averaged together — steadier than one at a time, still fast.
epoch
one full pass over the whole training set. Training runs 20–40 of them.
loss L
one number for "how wrong the model is". Training only ever tries to make it smaller.
gradient
per learned number: how much L changes when that number moves a hair. Points toward "less wrong".
learning rate η
how big each nudge is (e.g. 0.001). Too big: training jumps around. Too small: takes forever.
Adam
the nudging rule that smooths gradient direction and size; it adapts each number's step automatically.
backpropagation
computing all gradients in one backward sweep, layer by layer, reusing each layer's forward values.
overfitting
memorizing the training images instead of learning the symbols. Fought by held-out validation, variety in generation, and the λ penalty.
train / validation / test
three disjoint seed ranges: learn on the first, tune on the second, judge on the third — never the same crops twice.
confusion matrix
a table of true class vs predicted class. The diagonal is right; bright cells off it are the mix-ups to fix.
im2col
cutting every small window of the image into a row of a big matrix, so a whole convolution becomes one matrix multiply (and one backprop).
staff space
the distance between two staff lines — music's natural ruler. Nearly everything here is measured in it.
degradation
